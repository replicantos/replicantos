Harnesses

Bring your own sub.

You pay your providers directly. ReplicantOS has no account, no billing and no token resale. Each provider runtime is installed separately on your host and signs in the way that provider supports; v0.1 does not store provider credentials.

CX Stable

Codex

Talks to a host-installed Codex app server, with normalized events, tools and approval requests.

CL Stable · Optional

Claude Agent SDK

Uses the optional SDK when you install it, with explicit settings and permission callbacks.

OC Beta

OpenCode

Drives host-installed OpenCode sessions over ACP through the same run lifecycle.

GB Beta

Grok Build

Drives host-installed Grok Build sessions over ACP with normalized progress, usage and failures.

Persistent personas

Every Replicant, its own workspace.

Give each persona a name, a harness and a directory of its own. Sessions end. The next message can pick up the same provider session.

  • Dedicated workspace. Each Replicant works from its own workspace directory on your host.
  • Durable memory. Memory lives in a directory nested inside that workspace, where you can find it.
  • Session resume. An authorized channel message can enqueue a bound Replicant, resume its provider session and store its final reply.
  • Permissioned channels. Channels are permission-checked on the server, so your team only reaches the Replicants they are granted.

Inspectability

Runs you can actually inspect.

Runs leave a durable record you can open, read and argue with. Provider session identifiers stay in protected server state and out of the run views.

  • History and detail. Authenticated run history with bounded, normalized events.
  • Output and usage. Final output and usage are persisted with the run.
  • Approvals and cancellation. Approval decisions are recorded, and authorized people can request cancellation.
  • Diagnostics. On-demand harness diagnostics check that each provider runtime is installed and discoverable. They do not prove your login works.

Schedules and tasks

They show up on schedule.

Assign a Replicant to a cron schedule and it turns up on time, in your timezone. Track the rest of the work on a shared board.

Security

Locked down by default.

Your host, your credentials, your policy. Authorization is enforced on the server; hiding a button is never the control.

Roles your team can live with

Owner, admin and member roles with scoped allow and deny grants, enforced on the server.

Loopback by default

The default listener is loopback-only HTTP. Plain HTTP exposure beyond the host is rejected; put TLS at a same-host reverse proxy.

No telemetry

No telemetry is enabled by default. This site loads no third-party scripts or fonts either.

No default account

The first visit creates the owner. There is no seeded login or password to forget to change.

Masked database viewer

A masked, allowlisted SQLite viewer: protected columns stay masked and there is no arbitrary SQL.

Safe-root file editor

A UTF-8 file editor confined to approved roots by real path containment checks.

Install

If you don't like something, fork it.

ReplicantOS runs on your host, next to the provider runtimes you already use. replicantos.com never hosts a workspace or agent session. You need Node.js 22 or newer.

  • MIT. Take it, rename it, ship it.
  • Restyle it. Shared design tokens live in packages/ui.
  • Add a harness. Adapters implement one normalized contract under packages/harnesses.
SUPPORTED SOURCE PATH · V0.1.0 
git clone --branch v0.1.0 --depth 1 https://github.com/replicantos/replicantos.git
cd replicantos
corepack enable
pnpm install --frozen-lockfile
cp .env.example .env
pnpm build
pnpm run doctor
pnpm start

Open http://127.0.0.1:8787 and create the first owner. pnpm start never installs or builds silently.
